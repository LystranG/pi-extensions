# `/auto-rename` 设计草案

状态：用户已批准并完成实现，验证与审查记录见提交说明

## 目标与已确认行为

为 `@lystran/pi-session-rename` 增加无参数命令 `/auto-rename`，由用户手动触发独立模型请求，为当前会话重新生成名称。

用户已确认：

1. 根据当前分支的**会话整体主线**命名，而非只概括最近话题
2. 生成成功后直接覆盖已有名称，包括用户手动指定的名称；失败保留原名
3. 立即使用命令触发时的上下文快照，不等待正在执行的主对话结束
4. 重复执行时取消旧的命名请求，以最新一次请求为准

## 现有实现与可复用部分

- `plugins/pi-session-rename/src/index.ts`：通过当前模型的 `modelRegistry.complete()` 独立调用模型，并补齐 provider 路由头
- `plugins/pi-session-rename/src/controller.ts`：负责首次输入捕获、一次性触发、会话切换时取消请求及防止旧结果写入
- `plugins/pi-session-rename/src/title.ts`：提供标题提示词、清洗、长度校验和分类重试
- `plugins/pi-session-rename/src/session-history.ts`：当前只统计用户消息数量，需要增加命名上下文提取能力
- `docs/adr/0002-session-title-policy.md`：记录必须保留的命名与重试规则

当前自动流程在已有名称或已有历史时不触发，所以不能直接把新命令接到原有 `onBeforeAgentStart` 上。应新增显式重命名入口，共享模型请求与标题处理能力，分别表达两种触发策略。

## 命名规范

继续沿用现有规范：跟随用户语言；以动作和具体对象命名；保留代码标识符、路径、命令及错误码；输出单行纯标题；汉字不超过 20 个，非汉字词不超过 10 个，两项同时满足。

长度超限最多重试一次，无可用正文最多重试三次；provider 错误立即报告。重试上限相互独立，保持现有语义。

手动入口需要把现有系统提示中“首条用户消息”的限定改为会话上下文语义；格式与长度规则继续共享。首次自动命名的输入契约与行为应保留。

## 上下文提取建议

以当前分支的有效对话为依据，结合已有压缩摘要、用户消息与助手可见文本。输入只作为待概括的数据，不执行其中的指令。剥离技能说明等注入内容，默认排除思考过程、工具调用参数和大量工具原始输出；必要的结果优先从对话和摘要获取。

手动命名使用独立输入预算：每段最多 3000 字符、总计最多 16000 字符，两级截断都保留首尾并标记省略；这样兼顾摘要、任务起点与后续对话。首次自动命名保留原有首句 6000 字符预算。

有效上下文已被压缩或截断时，标题只能依据保留的信息；不额外调用模型重建完整历史。主模型尚未持久化的流式片段不应被承诺一定包含在快照中。

## 请求生命周期建议

每次手动请求固定会话身份、分支位置、当前模型、provider 路由信息、原有名称及命名输入。对话继续产生消息不使该快照失效。

- 手动请求取代尚未结束的首次自动命名或上一次手动命名
- 切换、关闭会话或主动跳转分支后，旧请求不得写入当前会话
- 取消请求之外，使用请求序号防止未及时响应取消的 provider 返回旧结果
- 最新有效请求成功后直接覆盖当前名称，不额外增加“请求期间名称变化则拒绝覆盖”的限制
- 恢复会话、分叉会话和已有名称会话均可手动命名
- 无有效上下文、无可用模型或调用失败时保留原名，并显示英文提示
- 命令提供生成中、成功及失败提示，独立请求不写入主对话消息

分支变更与正常新增消息需要区分，不能因 leaf ID 随普通对话推进而拒绝所有结果。相关公开 API 与事件细节见调研报告。

## 实现范围与验证建议

预计涉及入口注册、控制器、上下文提取、标题提示词及对应测试，并同步更新插件 README 与 changeset；不手动修改包版本或 CHANGELOG。

关键验证包括：恢复/已有名称会话可命名、整体主线上下文与压缩摘要提取、输入预算边界、首次命名与手动请求竞争、重复命令只有最新结果生效、切换会话或分支时旧结果失效、成功覆盖与失败保留，以及现有格式和 provider 路由行为不回归。

实现使用真实内存会话和可控模型替身进行离线验证，不调用真实网络模型；交付前运行 `bun run verify` 并执行规范与需求双轴审查。

## API 证据

公开 API 与最低版本兼容性已完成 [独立调研](./pi-session-rename-auto-rename.md)，结论为可实现：

- 用 `pi.registerCommand("auto-rename", ...)` 注册命令，不调用 `waitForIdle()`，不向主对话发送用户消息
- 从根包导入 `buildSessionContext`，使用 `buildSessionContext(ctx.sessionManager.getEntries(), ctx.sessionManager.getLeafId()).messages` 获取当前分支的有效上下文；在首次 await 前提取自有文本快照
- 复用 `ctx.modelRegistry.complete()`、provider 请求头适配器和 `pi.setSessionName()`
- `buildSessionContext` 根导出及 `complete` 已在本机 0.84.2 与 0.87.1 的公开声明中核对；不采用仅新版本存在的 `buildSessionProjection` 或 `streamSimple`
- 以独立 AbortController 和请求序号协调命名；在 `session_shutdown`、`session_tree` 等会话替换或分支跳转时使旧结果失效；失效检查先于对捕获的 pi/ctx 的访问

快照不包含尚未完成的流式回复及尚未交付的排队输入，也不保证等同于经过后续 hooks 变换的下一次模型请求。0.87.1 的命令分派顺序已有本机实现证据；0.84.2 的核心接口已核对，但忙时分派与失效时序仍应在实现阶段做针对性验证。
